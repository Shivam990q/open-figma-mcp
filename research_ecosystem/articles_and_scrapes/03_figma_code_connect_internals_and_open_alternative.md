### Executive Overview

In 2024, Figma released **Code Connect** ([`github.com/figma/code-connect`](https://github.com/figma/code-connect)), a tool designed to replace generic autogenerated code in Dev Mode with actual production component syntax (such as `@/components/ui/button` from shadcn/ui, MUI, Chakra, or proprietary design systems).

However, Figma gated Code Connect behind **Enterprise / Organization Dev Mode seats** and restricted code generation templates to static `.figma.tsx` files compiled with proprietary Figma CLI commands (`npx figma connect publish`).

In this investigation, we analyze the internal architecture of `@figma/code-connect`, its AST parsing mechanics, its property mapping schema, and detail how **OpenFigma's Open Code Connect** replaces it with zero cloud dependencies and zero license costs.

### 1. Internal Architecture of Official `@figma/code-connect`

From our forensic inspection of `research_ecosystem/repos/figma-code-connect/`:

```
figma-code-connect/
├── cli/
│   ├── figma-types.d.ts (Full type definitions for figma.* template bindings)
│   ├── src/
│   │   ├── connect/ (CLI parser and compiler for template files)
│   │   ├── parser/ (TypeScript compiler API AST visitor)
│   │   ├── publish/ (HTTP multipart upload to Figma's internal Code Connect API)
│   │   └── create/ (Scaffolding wizard generating starter templates)
├── react/ (React template macros and JSX string transformers)
├── compose/ (Android Jetpack Compose mapping engine)
└── swiftui/ (iOS SwiftUI component mapping engine)
```

#### The Template Authoring Model:
Developers write `.figma.tsx` files linking a Figma component URL to a React component:

```tsx
import React from 'react'
import { Button } from './Button'
import figma from '@figma/code-connect'

figma.connect(
  Button,
  'https://figma.com/design/AbC123XyZ/App?node-id=123:456',
  {
    props: {
      variant: figma.enum('Variant', {
        Primary: 'primary',
        Secondary: 'secondary',
        Destructive: 'destructive',
      }),
      size: figma.enum('Size', {
        Small: 'sm',
        Medium: 'md',
        Large: 'lg',
      }),
      disabled: figma.boolean('Disabled'),
      label: figma.string('Label Text'),
      icon: figma.instance('Leading Icon'),
    },
    example: (props) => (
      <Button
        variant={props.variant}
        size={props.size}
        disabled={props.disabled}
      >
        {props.icon}
        {props.label}
      </Button>
    ),
  }
)
```

#### How the Official CLI Parses & Publishes:
1. **TypeScript Compiler AST Extraction:**
   - The CLI (`figma connect publish`) runs `ts-morph` or the native TypeScript compiler (`tsc`) AST visitor over all `*.figma.tsx` files in the repository.
   - It validates that `figma.connect` calls contain valid Figma URLs and extracts the `props` mappings and `example` AST expressions into an intermediate JSON payload (`ResultSectionList`).
2. **Prop Resolvers:**
   - `figma.enum(figmaPropName, valueMapping)`: Maps Figma component variant strings to code enum/string values.
   - `figma.boolean(figmaPropName)`: Maps Figma toggle booleans to code booleans.
   - `figma.string(figmaPropName)`: Extracts text layer strings.
   - `figma.instance(figmaPropName)`: Recursively resolves nested child components (slots/icons).
3. **Cloud Synchronization:**
   - The CLI uploads the parsed JSON representation to `POST https://api.figma.com/v1/code_connect` requiring an enterprise access token.
   - In Dev Mode, when a developer clicks a component, Figma's web frontend matches the component GUID and injects the pre-rendered code snippet.

### 2. Limitations & Enterprise Roadblocks of Official Code Connect

1. **Paywall Lock-In:** Requires an active Enterprise plan ($35/mo per developer seat) to view Code Connect snippets in Dev Mode.
2. **Build-Time Friction:** Developers must run manual CLI publish steps on every design system release.
3. **No Dynamic Swarm Resolution:** AI agents cannot query Code Connect mappings dynamically without authenticating against Figma's cloud API.
4. **No Reverse Scaffolding:** Official Code Connect cannot inspect an arbitrary Figma library and auto-generate the mapping file; developers must write hundreds of `.figma.tsx` files by hand.

---

### 3. Open Code Connect: Architecture & Specification

OpenFigma implements **Open Code Connect** as a first-class, local-first engine built directly into the native Rust core and universal Node.js server:

```
+-------------------------------------------------------------+
| Open Code Connect Architecture                              |
+-------------------------------------------------------------+
| 1. Declaration Layer: code-connect.json (Production Config) |
| 2. Auto-Scaffolder: open-figma connect --scaffold          |
| 3. Resolution Engine: Fuzzy matching on component names,   |
|    variant sets, and node IDs                              |
| 4. Code Synthesizer: Maps props to JSX / Vue / Svelte       |
+-------------------------------------------------------------+
```

#### Automated Scaffolding (`open-figma connect --scaffold`):
OpenFigma traverses any Figma document or `.fig` archive, identifies all `COMPONENT` and `COMPONENT_SET` nodes, analyzes their variant properties, and instantly emits a fully typed `code-connect.json` scaffolding file.

#### Zero-Cost Integration with AI Coding Agents:
When an AI agent (Cursor, Claude Code, Lovable) invokes the `get_code_connect` tool, OpenFigma instantly matches the selected design node to the production codebase component, providing the agent with exact import paths and prop signatures. This ensures the generated code is 100% faithful to the existing design system with zero manual glue code.
